# 三层大容量LIF固定基线调整方案

2026-10-04。用户要求以5000＋3000＋2000三层隐藏LIF建立固定基线，当前阶段暂不研究生长。随后用户要求实施并由本人在PowerShell运行完整训练。三层代码与训练入口已实现，实际诊断和运行方式以[执行登记](large_lif_baseline_execution.md)为准；本文保留设计阶段预算与判断原则。旧小网络、出生对照与失败证据保留。

## 研究问题与本轮范围

将容量不足作为下一轮主假设，用显著更大的固定图检验任务学习能力。用户提供的ONN 3200＋1500及两次卷积经验是规模参考，不等价于本项目纯LIF全连接图的容量证明。现有实验不能把容量不足确定为唯一原因；本轮同时记录拟合与跨原始ID表现，判断大模型能否学好任务以及功能是否泛化。

此前“256”是D1每次出生的固定数量，或D2按Fire排名选择的父节点数量。前向没有每层最多256个节点发放的规则，也没有top-k发放门控。此前预设小幅单次加点并仅训练4遍，确实没有充分检验大规模容量。本轮不使用出生、拆分、删点、删边或复活操作，网络在训练期间保持完整固定结构；后续剪减另行登记。

## 模型与可训练参数

| 部分 | 规模 | 说明 |
|---|---:|---|
| 输入 | 每帧784维、8帧 | v5原灰度 |
| 隐藏层1 | 5000 LIF | 接全部输入维 |
| 隐藏层2 | 3000 LIF | 接前层全部实际Fire |
| 隐藏层3 | 2000 LIF | 接前层全部实际Fire |
| 输出 | 10＋7累积单元 | 不Fire、不leak，末态分组比较 |

共10000隐藏LIF、10017计算单元（输入维不计入该单元数）。相邻层全连接：输入边3,920,000，第一→第二层15,000,000，第二→第三层6,000,000，输出边34,000，合计24,954,000边权，各类密度1。任何节点都可以依自身阈值发放，不设按发放排名或绝对数量限制的门控。

仅训练这四组真实边权，不训练偏置、LIF泄露率或阈值。初始沿用固定泄露系数exp(-5/20)、阈值0.5、每帧4个5ms神经步，共32步/160ms神经时间；视频实际播放时间未规定。所有隐藏层之间只传前一神经步的二值Fire，第三层增加一级真实传播延迟，输出只积分第三层Fire加权信号。每视频开始清零膜电位、脉冲状态与输出。

前向硬阈值，反传沿用已披露代理导数1/(1+5|v-threshold|)^2；数字/运动两个末态交叉熵相加。AdamW、初始学习率0.001、weight decay 0.0001、梯度范数裁剪1。学习率计划在第50遍后降至0.0003、第80遍后降至0.0001，随优化器与检查点保存；这些是首轮登记配置，不开展多组合挑成绩。

## 实现与启动诊断

先扩展纯LIF前向、活动记录、梯度训练与检查点为三层，保留现有两层实现及可比较配置。逐层检查无模拟膜值通信、无隐含分类器、无节点数量门控，末态输出可由第三层真实Fire重建。

大层宽须使用与入边数量及初始实际Fire相匹配的初始化尺度，不能直接照搬512宽度的隐藏权重标准差。初始化校准只用固定的32个拟合视频、无标签反馈、无优化更新，最多3次整批前向；仅调整各层初始边权尺度，记录规则、实际尺度与逐层Fire。该诊断范围不是发放数上限；不通过改变阈值、削减层宽或挑模型种子补救初始化。

在实际5000/3000/2000图上做一次32视频前向与反传诊断，检查四组边权梯度有限且非零、三层有真实Fire、输出重建和视频边界清零。校准与梯度诊断最多128视频前向、32视频诊断反传，不混入优化训练成本。失活、饱和或非有限梯度时先修训练实现和初始化，不将故障当作容量实验结果。

使用项目`.venv`中的CUDA版PyTorch与RTX 5080 Laptop GPU。FP32权重、梯度和两份Adam状态理论约399MB，另需活动、自动微分、数据、缓存及工作区，实际显存以启动诊断测量为准。首选有效批量128；微批量可从32开始，显存充足时增加，必要时梯度累积保持有效批量。显存不足优先减微批量或重算中间活动，保留目标层宽。FP32作为首轮数值基线；若另采用混合精度须单独登记和核对硬Fire差异。记录显存峰值与设备墙钟，不承诺未经实测的训练时长。

## 数据、预算与训练完成判断

沿用v5和根种子20261004，模型唯一根种子11。原200个训练ID仍固定拆为160个拟合ID/4480视频、40个结构控制ID/1120视频；原100个验证ID/1400视频不参与逐轮训练选择，最终测试封存。缓存和manifest哈希、具体ID保持现有协议。需要明确：4480个增强视频不等于4480种不同笔迹，拟合原始ID只有160个。

首段预算最多100遍，先完成至少50遍再考虑因性能平台停止。每5遍评估全部控制池（最多20次、22,400视频前向），每10遍评估全部拟合池的当前冻结模型（最多10次、44,800额外视频前向）；优化本身最多448,000视频前向及同数反传。所有评价均报告数字、运动、联合准确率和混淆矩阵，而非仅训练中的平均损失。逐层每帧/视频Fire、每LIF每步发放率、静默与高发放节点数量也须保存。

前50遍除运行故障、非有限数值或持续失活/饱和外，不按3次短平台提前终止。第50遍后结合预定学习率下降，只有连续4次控制检查（跨20遍）未形成新的可接受结果，且最后两个拟合检查也无改善，才登记平台并停止或转向。可接受结果指联合至少比历史最好提高0.5个百分点，数字与运动各不下降超过1个百分点；仍保留全部检查点/指标，不将门槛未过称模型收敛。

达到100遍预算时若拟合或控制仍在改善，应登记后续预算并继续同一模型、优化器、学习率及随机流，不把预算到期称训练完成。若拟合准确率已经高而控制准确率低，优先检查数据覆盖、增强与泛化；若大图连拟合池也学不好，先检查梯度、发放和时间表征。两种情况均不以低准确率下大规模删减作为成功。

冻结候选后另登记一次跨原始ID验证的模型哈希与评价预算；同一验证池曾被旧研究使用，结果仍按探索性确认解释。因为本轮同时改变层数和宽度，应称“大容量三层基线”，不能声称严格单变量容量对照。
