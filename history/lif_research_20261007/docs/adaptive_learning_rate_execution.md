## 反馈规则与完整状态

使用本地PyTorch的ReduceLROnPlateau，监控完整1120视频控制池的数字＋运动交叉熵，越低越好。相对历史有效最好值下降超过1%才重置平台计数；连续2次控制评价未达到该改善，学习率减半。控制仍每5遍评价，所以通常跨10遍形成两个未改善检查。下降后冷却1次控制评价，最低学习率1e-5；不按单批损失或某一次准确率波动降率。

接续时读取安全检查点已经完成的第5/10/15遍控制结果，只继承实际反馈，绝不重写历史学习率。两次连续未改善已成立，因此在接续时实际降一次0.001→0.0005；历史再长也不会在接续瞬间连降多次。调度器最佳损失、未改善次数、冷却次数、最后已处理的控制遍数与实际下降次数存入完整检查点，随模型、Adam状态和所有RNG恢复。恢复已完成评价不会重复计数。

前50遍不因性能平台停止。之后要求至少2次实际学习率下降、距最近下降生效至少20遍、控制连续4次和拟合连续2次未形成原登记改善，才考虑平台停止；不再使用固定第70遍条件。活动/数值故障仍可提前停止。总预算100遍包含原15遍，达到预算不称收敛；扩大预算或故障/平台后继续须登记原因。

首次接续（也可添加--prepare-only仅建立并核对状态，不训练）：

```powershell
Set-Location E:\project\brain-grow
```

```powershell
Set-Location E:\project\brain-grow
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -u -m tools.train_adaptive_baseline --resume --epochs 100
```

Ctrl+C仍在有效批次边界安全保存。逐批日志、每遍指标、控制/拟合完整混淆矩阵及逐层Fire记录沿用；新增learning_rate_events.jsonl记录触发依据、下降前后学习率、冷却/平台计数和生效遍数。每遍同时记录实际训练学习率及下遍学习率。成本累计包括父实验，墙钟按运行会话分别披露；Fire与边数仍不是实测能耗。父实验最佳模型留在原best.pt，新目录仅在接续后的控制分数超过原最佳时写入自己的best.pt。

代理后台启动时，控制台输出保存为console.log，错误保存为console_error.log。后台运行也可以用以下命令请求安全暂停，不能再次用--resume启动重复进程；入口的running.json排他锁会拒绝已有运行进程的重复启动：

```powershell
.\.venv\Scripts\python.exe -u -m tools.train_adaptive_baseline --request-stop
```

该命令只写暂停请求，不强制结束。需等待后台日志显示保存/退出；之后使用--resume恢复。强制结束遗留的锁只有在确认原PID不存在后才自动归档，检查点和成本日志仍按原恢复规则保留。
