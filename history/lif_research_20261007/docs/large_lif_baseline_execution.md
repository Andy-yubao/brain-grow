## 固定模型与训练配置

三层5000/3000/2000隐藏LIF共10000，固定17个非LIF输出累积单元；共24,954,000边权，四组尺寸784×5000、5000×3000、3000×2000、2000×17，全部全连接。只训练边权，无偏置、卷积、额外表征或分类器。每层均读取前一神经步的真实Fire，所有节点独立按阈值发放，没有top-k或256发放数限制。固定泄露exp(-5/20)、阈值0.5、每帧4×5ms，共8帧/32神经步/160ms神经时间，视频实际播放时长未规定；视频边界状态全部清零。

前向硬Fire，反传代理导数1/(1+5|v-threshold|)^2。两个末态分组交叉熵相加，AdamW(foreach=False)，weight decay 1e-4，梯度范数裁剪1；第1–50遍lr=0.001、第51–80遍0.0003、第81遍起0.0001。FP32、最高精度矩阵乘、禁用TF32、确定性算法。有效批量128，默认微批量32并按样本数加权累积梯度；输入v5、模型根11和数据根20261004沿用，拟合160原始ID/4480视频、控制40ID/1120视频，原验证/封存测试不解包或评价。

## 初始化与必要诊断

隐藏边权初始标准差0.15×sqrt(784/fan-in)，输出边权0.02×sqrt(512/2000)。从拟合视频用私有根11排列取32个固定视频，校准只读像素、不读标签、不更新优化器。最多3次全批前向，逐层每LIF每步Fire率[0.005,0.25]作为初始化健康诊断区间；不截断Fire。每次只调整最靠前的异常层：低发放时按正膜值RMS放大入边，高发放时缩小入边，具体公式、倍率和每次统计保存在calibration记录。此校准改变初始权重尺度，不改变LIF泄露和阈值，也不挑种子。

校准通过后，同32视频做1次前向/反传，检查四类边权梯度有限且非零、真实Fire与末态输出重建。启动预算最多96校准前向＋32诊断前向＋32诊断反传，0次优化器更新；失败保留证据并停止，不进入长训练。视频边界、三层传播延迟、超过256节点同时发放、有效批量累积与完整优化器/RNG恢复另由真实LIF行为检查覆盖。

## 训练预算、评价与停止条件

首段最多100遍，优化最多448,000视频前向与同数反传。每5遍评价1120控制视频（最多20次/22,400前向），每10遍评价4480拟合视频（最多10次/44,800前向）。两池指标包括数字/运动/联合准确率、混淆矩阵、实际每帧/视频Fire、每LIF每步发放率、逐层静默和高发放数量、资源/密度。控制结果参与选择，不能称独立验证；不因未查原验证而将控制结果当作最终成绩。

控制池可接受改善为联合≥历史接受点+0.5个百分点、数字/运动各下降不超过1个百分点。连续4次控制检查未达此改善，且连续2次拟合检查既没有交叉熵下降至少0.001、也没有数字＋运动＋联合分数上升超过0.002，才考虑平台。第51/81遍学习率下降会清空平台计数，并给第一次下降至少20遍，故性能平台最早第70遍停止；运行/非有限数值或持续失活/饱和故障可提前停。最高控制三项之和对应的best.pt另保存，不将平台停止称收敛。

OOM仅在优化器更新前的前向/反传区间重试：清空本有效批次梯度，减半微批量，按原样本顺序重跑，有效批量和目标层宽不变；已完成工作及失败尝试分别记账。优化器step异常不重试可能部分更新的状态，只保留上一个安全检查点。重试、中断评价重跑或强制终止后的回放会有额外成本，不混入登记基本预算。

达到100遍是预算节点。若仍有改善，后续需要明确记录续训原因与预算，恢复原模型/优化器/随机流；入口不会自动无限训练。扩大预算须带--extension-reason。两次持续活动故障或平台停止后的继续也须登记原因，不以不断重启消除失败证据。

## PowerShell命令与日志

默认目录为`experiments/runs/large_lif_baseline_v1/`。实施阶段先准备完整大图的初始检查点：

```powershell
Set-Location E:\project\brain-grow
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -u -m tools.train_large_baseline --prepare-only
```

准备完成后，用户开始100遍训练以及之后中断恢复均用：

```powershell
Set-Location E:\project\brain-grow
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe -u -m tools.train_large_baseline --resume
```

入口每5个有效批次和每遍结束显示进度；每5/10遍分别显示控制/拟合准确率。Ctrl+C会请求安全停止，完成当前有效批次后保存再退出；请等待“检查点已保存”或“运行结束”。训练时最新安全状态在`resume.pt`，上一安全状态在`resume_previous.pt`，最佳控制状态在`best.pt`。检查点包含模型、AdamW状态、学习率、当前遍的完整样本排列与位置、损失累积、NumPy/Torch/CUDA随机状态及实际成本。

若在评价途中停止，恢复只重跑该尚未完成的评价，保留已发生的前向成本。若直接关闭窗口/强制结束，可能回放上个安全检查点以来的训练；完整成本日志保留，尚未写入日志的在途工作无法精确计量。坏的最新文件可回退上一检查点。启动后源码哈希/数据哈希/有效批量不一致时拒绝静默恢复。

每遍`epoch_XXX.json`，逐批`cost_journal.jsonl`，每次评价的JSON/NPZ在`evaluations/`，每次控制评价保留模型快照在`checkpoints/`，配置/源码/开始提交与差异留在运行目录。检查点采用最新＋上一＋最佳完整状态，以及每5遍模型快照的保存方式，100遍预计约3GB数量级文件；不保存100份完整Adam状态。Fire和连接数量是资源代理，不是实测能耗。没有付费依赖或ONN修改。
