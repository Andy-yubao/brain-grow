# 工作区精简流程

本流程用于持续保持项目根目录简洁，避免状态文档和实验实现无限累积。执行清理时保留可追溯证据，不改 `tmp/`，不擅自删除数据或环境。

## 每次清理顺序

1. **盘点并冻结边界**：读取 `AGENTS.md`、当前目标/框架/状态、数据协议和实验计划；查看 Git 状态、未提交修改、活动入口、运行目录和跨文件引用。不得覆盖或丢弃未提交文件。
2. **先备份记录文档**：把准备压缩的 `status.md`、`current_framework.md` 等完整原文复制到 `history/workspace_snapshot_YYYYMMDD/docs/`，在备份索引写清快照日期。先备份再编辑。
3. **压缩当前文档**：状态页只保留当前阶段、最近结果、下一步、数据/恢复约束；框架页只保留长期目标与当前边界。旧轮细节留在报告/执行记录，不在状态页重复抄录。检查目标、状态、计划和入口之间没有冲突。
4. **整理报告包**：将 `reports/` 中的报告、JSON、图片和 evidence 按日期与实验系列整体移动到 `docs/reports/YYYY-MM-DD/<experiment>/`。保留文件名；更新所有 Markdown 链接和仍在使用的报告生成器输出路径；维护 `docs/reports/README.md`。
5. **清退已结束实现**：仅在确认不会被当前训练入口、恢复入口、配置、测试或后续计划引用后，将旧配置、工具、模块、测试、执行登记与完整运行目录一起移到 `history/<阶段包>/`，并写 `ARCHIVE.md`。当前依赖实现保留；历史报告留在 `docs/reports/`。归档前用文本搜索核对依赖和引用。
6. **保留临时区**：除非用户另行授权，`tmp/` 和 `.tmp/` 内文件不删除、不移动。
7. **复核**：检查报告链接、代码入口、配置来源和历史索引；运行 `python -m tools.check_workspace`。仅修复本次移动引起的问题，不追加无关测试或训练。
8. **记录清理结果**：更新本流程文档的归档索引；复核 `git status` 与差异，按项目规则提交清理变更，并记录移动范围、保留入口、检查结果和未完成事项。
